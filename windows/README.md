# Windows専用PCのコモ管理

開発PCからGitで配布したプログラムを、本番Windows PCで起動・終了・更新するためのランチャーです。日常運用ではデスクトップの **コモ管理** を開きます。Windows標準のPowerShell 5.1とWPFを使い、追加のPython実行環境は不要です。

## 初回だけ：本番Windows PCで設定する

1. コモを日常利用するWindowsアカウントにログインします。
2. Git・Docker Desktop・Microsoft Edgeをインストールし、Docker DesktopでLinuxコンテナーを使える状態にします。Docker Desktopの初回利用条件・WSL等のセットアップは先に済ませます。
3. 本番配布リポジトリを、今後動かさない場所（例 `C:\CHU-AI`）にcloneします。同期先のブランチを追跡する設定にします。
4. `src\.env` に本番の接続情報を設定します。存在しない場合はセットアップが `.env.example` から作成します。Google Sheetsを使う場合は、既存のREADMEに沿ってサービスアカウントJSONと保存先も設定します。
5. `windows\setup.cmd` をダブルクリックします。
6. 設定後に開く「コモ管理」で「コモを開く」を押し、初回の知識の準備が終わるまで待ちます。
7. チャットで既知の質問に回答できることを確認します。Windowsをいったんログアウトし、再ログインでコモが自動で開くことを確認します。

セットアップは既存の `.env` を残し、管理用キーが空またはサンプル値ならランダムに生成します。専用PCの自動入場用に `COMO_KIOSK_AUTO_LOGIN=true` を設定します。管理用キーは操作記録に出さず、知識管理画面へはURLのフラグメントで渡します。

デスクトップに「コモ管理」と「コモの使い方」を作ります。自動起動は現在のユーザーのログイン時タスクとして登録します。学校PCのポリシー等でタスク登録が許可されない場合は、そのユーザーのスタートアップフォルダーへ登録します。Windowsの自動ログインやパスワードの変更は行いません。

## 日常操作

| ボタン | 動き |
|---|---|
| コモを開く | Docker Desktopの準備を待ち、アプリを起動。知識の準備を確認してEdgeで全画面表示 |
| 知識を更新 | APIの起動を待って管理画面を開く。初回準備中・失敗後も、状態確認や再実行が可能 |
| コモを再起動 | このプロジェクトのサービスを停止・再起動して、コモを開き直す |
| 本日の利用を終了 | `docker compose stop` でこのプロジェクトのサービスを停止。知識・DB・集計等は削除しない |
| アプリを更新 | 現在追跡しているGitブランチを `git pull --ff-only` で更新し、Dockerを再ビルド・起動 |
| 操作記録を開く | ローカルの操作記録をメモ帳で表示 |

全画面のコモは **Alt + F4** で閉じられます。終了操作ではEdge全体や他のアプリを強制終了しません。Windowsの電源を切る操作は、サービス停止が終わってからスタートメニューで行います。

初回・更新後は、イメージの作成と検索データの準備に時間がかかります。ランチャーは別プロセスで処理するため、進捗表示やウィンドウ操作は継続します。health応答だけで準備完了とせず、知識管理APIの初期化状態も確認します。

初回準備が別の画面ですでに進んでいる場合は、その処理の完了を待ちます。準備を待つ間も「知識を更新」は押せるため、管理画面で進み具合を確認できます。知識の反映中は、終了・再起動・アプリ更新を止めて案内します。APIへ接続できない故障時は、復旧のため終了・再起動を実行できます。

## USBでの知識更新

日常の更新はGitの操作をせず、「知識を更新」から行います。Wordは `.docx`、そのほか `.txt` と `.md` に対応します。USBの特定のドライブ文字やフォルダー名は要求しません。

`quick-guide.html` はA4で印刷できる1枚の手順書です。USBの図解を入れています。実機のUSB差込口には「コモ更新用」のシールを貼り、必要に応じて設置PCの写真を添えてください。

## Git更新とデータの扱い

プログラムは本番リポジトリの現在の追跡ブランチから受け取ります。ランチャーがブランチを変更したり、強制リセットしたりすることはありません。編集途中の追跡ファイルやGitの競合がある場合、更新を止めて案内します。

知識更新画面で取り込んだ知識や更新履歴は本番PCの `data/`、検索DBはDockerの永続ボリュームで保持します。`.env`・`secrets/` も本番PCに保持します。これらはGitのコード更新から分けて扱います。おみくじ集計は従来どおり、同じURLを開くブラウザの保存領域に残ります。ランチャーは固定の `http://127.0.0.1:8000` を使用します。

アプリ更新は使っている人がいない時間に行ってください。更新失敗時の詳細は「操作記録を開く」で確認できます。既存のGitHub間同期のワークフローは変更しません。

## 自動起動の解除・再設定

`windows\disable-autostart.cmd` を開くと、このリポジトリ向けのログイン時自動起動を解除します。デスクトップの管理アイコンと保存データは残ります。再登録は `setup.cmd` を実行します。

リポジトリを別の場所へ移す場合は、移動する前に自動起動を解除し、移動後にセットアップし直してください。

## 記録と障害対応

- `data/windows-launcher/operations.log`: 秘密値を伏せた操作記録
- `data/windows-launcher/operation.json`: 現在または最後の操作
- `data/windows-launcher/runtime.json`: コモの稼働確認結果
- `data/windows-launcher/setup.json`: 自動起動の登録方法・日時

Dockerが準備できない場合はDocker Desktopの表示を確認します。知識の初期化が失敗した場合は管理画面の案内と接続設定を確認して再実行します。ランチャーを閉じても、すでに始めた起動・更新処理は継続します。

## 確認範囲

Windows以外の開発環境ではWPF・タスクスケジューラ・Edge・Docker Desktopの実機操作は検証できません。配布前に本番Windows PCで、初回設定、ログイン後の自動起動、終了、再起動、USBからの更新、履歴復元、Git更新、ネットワーク不通時の案内を確認してください。

日本語のPowerShellファイルはWindows PowerShell 5.1で読めるUTF-8 BOM付きです。設定ファイル・状態JSON・操作記録は明示的にUTF-8で読み書きします。
